# REQS.md: Product Metadata Service (Read-First)

## 1. Структура базы данных (PostgreSQL)
Для обеспечения масштабируемости и возможности шардирования (распределения данных по разным серверам) используются `UUID` в качестве первичных и внешних ключей.

### 1.1. Таблица `categories`
Служит справочником категорий для иерархической организации товаров.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **category_id** | `UUID` | Primary Key. Уникальный ID категории. |
| **name** | `VARCHAR(255)`| Название категории (например, "Смартфоны"). |
| **parent_id** | `UUID` | Ссылка на родительскую категорию (для вложенности). |
| **updated_at** | `TIMESTAMPTZ` | Дата последнего изменения. |

### 1.2. Таблица `products`
Основная таблица метаданных товаров.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **product_id** | `UUID` | Primary Key. Уникальный ID товара. |
| **category_id** | `UUID` | Foreign Key. Ссылка на таблицу `categories`. |
| **is_active** | `BOOLEAN` | Флаг доступности (позволяет быстро отсекать неактивные записи). |
| **payload** | `JSONB` | Метаданные: характеристики, теги, ссылки на изображения. |
| **updated_at** | `TIMESTAMPTZ` | Метка времени для инвалидации кэша и отслеживания изменений. |
### 1.2. Основные индексы
* **B-tree (`product_id`)**: Для точечных запросов и Bulk-выборок.
* **B-tree (`category_id`)**: Оптимизирует поиск товаров внутри конкретных категорий.
* **GIN (`payload`)**: Позволяет выполнять поиск по атрибутам внутри JSON (например, поиск по тегам или свойствам).

## 2. Требования к системе и Infrastructure (Текущее состояние)

### 2.1. In-memory Cache
* **Реализация**: Внедрение Redis или локального кэша (BigCache) в Go-приложение.
* **Логика**: Снижение нагрузки на PostgreSQL при высокой частоте чтений (Read-First подход).

### 2.2. Kubernetes (Реализованная инфраструктура)
Проект развернут в K8S и включает следующие компоненты (папка `/infra`):
* **Database (`/db`)**: Deployment, Service, PVC для данных, Secret для доступов.
* **Monitoring (`/monitoring`)**: Prometheus (ConfigMap, Deployment, Service, RBAC).
* **Application (`/worker-pool`)**: Основной сервис (Deployment, Pod, Service).

### 2.3. Метрики (Prometheus)
Сервис экспортирует данные на эндпоинт `/metrics`:
* **RPS (Requests Per Second)**: Интенсивность входящих запросов.
* **Latency (p99/p95)**: Время обработки ответа (критично для Middle-разработчика).
* **Cache Hit Ratio**: Эффективность работы кэша.
* **DB Stats**: Статистика пула соединений.

### 2.4. Worker Pool Pattern
* **Реализация**: Пул горутин ограничивает количество параллельных операций с БД и парсинга JSON, обеспечивая защиту от перегрузки CPU и утечек памяти.

## 3. HTTP API

### 3.1. GET /v1/products/{product_id}
* Получение метаданных конкретного товара по его ID.

### 3.2. POST /v1/products/bulk
* Пакетное получение данных по списку ID. Используется для формирования страниц поиска и витрин.

## 4. Потенциальное развитие (Roadmap)

### 4.1. Сетевой доступ и Безопасность
* **Service -> Ingress**: Настройка Nginx Ingress Controller для управления внешним трафиком.
* **Rate Limiting**: Ограничение количества запросов на уровне Ingress для защиты от DDoS и перегрузки сервиса.

### 4.2. Наблюдаемость (Observability)
* **Логирование (ELK / Loki)**: Внедрение структурированных логов и их сбор в централизованную систему.
* **Визуализация (Grafana)**: Создание дашбордов для мониторинга RPS, Latency (p99) и состояния Worker Pool в реальном времени.

### 4.3. Автоматизация (CI/CD)
* **CI Pipeline**: Автоматический запуск линтеров (golangci-lint) и тестов.
* **CD Pipeline**: Сборка Docker-образа и автоматический деплой в K8S при пуше в main-ветку.

### 4.4. Интеграция с ИИ
* **AI Enrichment**: Автоматическое создание описаний и тегов на основе содержимого `payload`.
* **Smart Classification**: Использование ML для автоматического определения категорий товара.

### 4.5. Расширенные запросы
* **Full-text Search**: Реализация текстового поиска по описаниям внутри JSON.
* **gRPC**: Переход на бинарный протокол для ускорения межсервисного взаимодействия.
